## Шаг 0. Проверка clean-room — до любого переноса

В `NNN` действует жёсткое правило: код пишется с нуля, без заимствований из
сторонних программ того же назначения. Перед переносом спросить владельца:

- весь ли код `pr 5` написан им самим (или для него);
- есть ли в `pr 5` файлы, строки, идентификаторы или ресурсы, взятые из чужой
  программы «экран → IP-камера» или её разбора.

Такие части не переносить. Их нужно реализовать заново по открытым
спецификациям (ONVIF, WS-Discovery, RTSP) и сказать об этом владельцу.
Сторонние библиотеки с открытой лицензией подключать как зависимости, а не
копировать в репозиторий.

## Шаг 1. Опись `pr 5` — ничего не менять

Составить и показать владельцу краткую опись:

- язык, система сборки, зависимости, точки входа;
- что делает каждый модуль;
- что пересекается с `NNN` (захват экрана, кодирование, RTSP, ONVIF,
  WS-Discovery, разбор аргументов, конфигурация) и что в `NNN` отсутствует;
- что переносить нельзя или незачем: собранные файлы, `build/`, `.exe`,
  пароли, ключи, личные пути, содержимое `.vs/`.

Для каждого пересечения предложить одно из трёх: оставить версию `NNN`,
заменить версией `pr 5`, объединить. Дождаться согласия владельца.

## Шаг 2. Перенос

- Работать в новой ветке от `claude/stoic-maxwell-13801d` (или от `main`, если
  pull request #2 к тому моменту слит). В `main` напрямую не отправлять.
- Переносить по одному модулю за коммит, не одним большим коммитом.
- Раскладка по целям CMake:
  - логика без GStreamer — в `s2rtsp_core`; эта библиотека не должна от него
    зависеть, иначе тесты перестанут собираться;
  - всё, что требует GStreamer, — в приложение `s2rtsp`;
  - код только для Windows — под `#ifdef _WIN32`; сетевые различия — через
    `src/net_compat.hpp`.
- Привести перенесённый код к стилю `NNN`: C++17, комментарии и сообщения на
  русском, отступ 4 пробела, `#pragma once`, поля класса с суффиксом `_`.
- Новая зависимость — в `pkg_check_modules` в `CMakeLists.txt`, в команду
  `vcpkg install` в `README.md` и в оба задания `.github/workflows/ci.yml`.
- На каждую перенесённую часть логики — модульный тест в `tests/`
  (каркас `tests/check.hpp`).

## Шаг 3. Проверка

После каждого коммита:

```bash
cmake -B build -S . && cmake --build build -j4
ctest --test-dir build --output-on-failure
```

На Windows: `cmake --build build --config Release` и
`ctest --test-dir build -C Release --output-on-failure`.

Перед завершением:

- оба теста (`unit`, `smoke_rtsp`) проходят, CI зелёный на Linux и Windows;
- на Windows вручную: `s2rtsp.exe`, поток открывается в VLC по
  `rtsp://<IP>:8554/stream`, устройство видно в ONVIF Device Manager;
- `README.md` и `CLAUDE.md` обновлены под новые модули и параметры;
- этот файл (`docs/pr5-migration.md`) удалён.

## Чего не делать

- Не отключать и не удалять тесты, чтобы добиться зелёного CI.

  аппаратное кодирование в CI не проверяются, только вручную на Windows.
